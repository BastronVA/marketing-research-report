# Marketing Research Report

Постоянный интерактивный шаблон для представления маркетингового исследования, подготовленного аналитическим GPT.

## Состав проекта

### Интерфейс отчёта

- `index.html` — оболочка отчёта.
- `styles.css` — адаптивное и печатное оформление.
- `app.js` — загрузка и отображение JSON.
- `report-data.schema.json` — единый контракт данных.
- `sample-report-data.json` — демонстрационный набор данных.
- `reports/index.json` — список доступных исследований и отчёт по умолчанию.
- `reports/<report-id>/manifest.json` — метаданные исследования и пути к материалам.
- `reports/<report-id>/report-data.json` — основной источник данных для интерфейса.

### Настройка аналитического GPT

- `GPT_ANALYST_INSTRUCTIONS.txt` — текст для поля Instructions.
- `01_research_methodology.md` — `09_quality_check.md` — файлы Knowledge.
- `sources-template.csv` — структура реестра источников.

### Работа с Codex

- `AGENTS.md` — постоянные правила работы с репозиторием.
- `CODEX_SETUP_PROMPT.md` — стартовая задача для развития шаблона.

## Как запустить отчёт

### Самый простой способ

Если не хотите вводить команды в терминал:

- **Windows:** дважды кликните `open-report.bat`.
- **macOS:** дважды кликните `open-report.command`.
- **Linux:** запустите `python3 open-report.py` из папки проекта.

Скрипт сам запустит локальный сервер, откроет браузер и покажет отчёт `crp-2026-06-09`.

### Через терминал

Можно открыть `index.html` напрямую и выбрать файл через кнопку **«Загрузить JSON»**.

По умолчанию приложение загружает исследование `crp-2026-06-09` из `reports/crp-2026-06-09/report-data.json`. Для автоматической загрузки отчётов из каталога `reports/` запустите локальный сервер:

```bash
python3 -m http.server 8000
```

Затем откройте:

```text
http://localhost:8000
```

Можно открыть конкретное исследование по идентификатору:

```text
http://localhost:8000/?report=crp-2026-06-09
```

Ручная загрузка локального JSON через кнопку **«Загрузить JSON»** сохраняется для проверки новых или внешних отчётов.

### Если нужен обычный публичный URL

Чтобы открыть отчёт просто по ссылке в браузере без локального сервера, разместите репозиторий на статическом хостинге, например GitHub Pages. После публикации URL будет выглядеть так:

```text
https://<ваш-аккаунт>.github.io/<repo-name>/?report=crp-2026-06-09
```


## Добавление новых проектов через интерфейс

На публичной странице GitHub Pages можно нажать **«Добавить новый проект»** в боковой панели, загрузить четыре файла исследования и сохранить проект в локальный каталог браузера:

- `report-data.json`;
- `research-report.md`;
- `assumptions-and-gaps.md`;
- `sources.csv`.

Такой проект не перезаписывает встроенный отчёт `crp-2026-06-09`: он хранится отдельно в `localStorage` конкретного браузера и появляется в переключателе проектов как **«Локальный»**. Его можно открыть через переключатель или по ссылке с `?report=<id>` на том же устройстве/в том же браузере.

Важно: GitHub Pages — статический хостинг, поэтому браузер не может сам записать загруженные файлы обратно в репозиторий. Чтобы новый проект стал виден всем пользователям и на всех устройствах, добавьте его отдельной папкой в `reports/<report-id>/` и зарегистрируйте в `reports/index.json`.

## Рабочий процесс

1. GPT-интервьюер формирует заполненный бриф.
2. Бриф загружается в аналитический GPT.
3. Аналитический GPT создаёт:
   - `research-report.md`;
   - `report-data.json`;
   - `sources.csv`;
   - `assumptions-and-gaps.md`.
4. Материалы складываются в `reports/<report-id>/`, а пути регистрируются в `manifest.json` и `reports/index.json`.
5. `report-data.json` загружается в интерфейс отчёта автоматически по `?report=<report-id>` или вручную через кнопку загрузки.
6. Готовый отчёт просматривается в браузере или сохраняется в PDF.

## Настройка GPT

1. Создайте отдельный GPT.
2. Вставьте содержимое `GPT_ANALYST_INSTRUCTIONS.txt` в Instructions.
3. Добавьте девять методических `.md`-файлов и `report-data.schema.json` в Knowledge.
4. Включите Web Search и Code Interpreter / Data Analysis.

## Принципы

- Бриф считается контекстом и набором гипотез, а не доказательством.
- Значимые утверждения проверяются по открытым источникам.
- Факты, слова пользователя, расчёты, выводы и допущения разделяются.
- Все оценки рынка содержат формулы, источники и сценарии.
- Полный анализ хранится в Markdown, а компактное представление — в JSON.
